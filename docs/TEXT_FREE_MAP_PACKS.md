# 本地混合标注地图包

## 需求与边界

设备在 heading-up（航向朝上）模式下会旋转底图。用户选择使用独立 POI 的级别，
需要去除道路名、地区名、山峰名和 POI 名称等全部瓦片文字；其余级别仍使用带字瓦片。
当前默认 z16–18 无字并启用独立 POI，z1–15 将文字直接渲染到瓦片。
本功能在 Center 中从用户选择的 OSM PBF 本地绘制栅格底图，独立 POI 仍使用已有提取器。
设备端的旋转、POI 读取、文字保持正向绘制不在此改动范围内。

底图接收道路、小径、铁路、水系、建筑和土地覆盖几何。
未勾选独立 POI 的级别绘制 PBF 中的地名、道路名、区域名和命名节点；
使用世界坐标对齐的标签网格控制密度，并优先显示城市等重要地名。
选区内的真实 OSM 城市名从 z1 起作为区域定位标注显示；选区外地名保持常规缩放阈值。
被勾选级别完全不执行文字绘制，POI 名称保留在 `maps/poi` 数据中。
道路名和地区名尚未提供独立动态标注数据，因此高缩放的动态文字只包括已支持的 POI 类别。
本功能不会从既有图片擦除文字，也不会使用在线成品底图作为回退。

## 用户操作

1. 打开地图包制作，选择区域和缩放级别。
2. 启用 POI，选择一个覆盖该区域、包含完整几何的 `.osm.pbf`。
3. 选择 OSM 和/或 Terrain，选择 POI 类别及独立 POI 缩放级别，保留瓦片 POI 索引输出。
4. 导出到文件夹。完成后将其中整个 `maps` 目录复制到 SD 卡根目录。

开启 POI 后，OSM 和 Terrain 从 PBF 本地生成，不会下载或复制原先带标注的瓦片缓存。
未开启 POI 时，旧的普通栅格缓存导出行为不变。
PBF 不能生成卫星影像，开启此模式同时选择 Satellite 会在生成前报错。
如果选择等高线，继续使用现有等高线生成和透明线条瓦片导出；缺失瓦片会阻止发布完整包。
等高线的数据准备可能需要网络和 Earthdata 配置，与本地底图渲染独立。

## 输出格式

```text
maps/
  map-pack.json
  base/
    osm/{z}/{x}/{y}.png
    terrain/{z}/{x}/{y}.png       # 选中时输出
  contour/{profile}/{z}/{x}/{y}.png  # 选中时输出
  poi/
    manifest.json
    pois.jsonl                  # 选中全量输出时生成
    index/{z}/{x}/{y}.jsonl
    icons/                      # 既有预留目录，不包含生成的图标
```

瓦片为 256×256 PNG，坐标为 WGS84/Web Mercator XYZ，与固件现有底图路径兼容。
`map-pack.json` 记录样式版本、源 PBF SHA-256、选区、缩放、图层以及
`labelled_zoom_levels`、`text_free_zoom_levels`、`poi_symbols_in_basemap=false`。
版本 2 的 `text_in_basemap` 表示是否存在带字级别；逐级行为以两个级别数组为准。
它们由同一份独立 POI 选择集合计算，不能分别编辑。
归属信息记录在 manifest 中，不烧录到瓦片像素。

输出的独立 POI 仍为已有 JSONL 规范（Compact 也是 JSONL），不是新的设备二进制格式。
POI 范围、类型覆盖、按优先级截断规则没有在本改动中扩大。

## 生成与失败语义

- 依次扫描 PBF 的节点、道路/面和多面关系，使用临时 SQLite 存放坐标、几何和空间索引。
- 按瓦片查询并流式绘制几何，避免每张图遍历整个区域或把区域所有几何常驻内存。
- 源 PBF 必须位于目标 `maps` 目录之外。
- 先在输出目录旁的唯一临时目录生成全部底图、POI 和所选等高线。
- 任何提取失败、无可绘制数据、缺少关系成员或用户取消都不会替换已有地图包。
- 发布时把原 `maps` 移到同级 `maps.previous-...`，再把完整新包移到 `maps`。
  若第二步失败，恢复旧目录。旧包保留供用户恢复；复制到 SD 时只需复制新的 `maps`。
- 临时几何库在完成/失败后清理。旧包备份会额外占用磁盘，用户可在验证新包后移走它。

## 当前样式能力

这是 Trail Mate 自己的基础样式，不是 OpenTopoMap 视觉复刻。
Terrain 是土地覆盖配色，没有由 PBF 推导的高程阴影；等高线仍为独立图层。
OSM 支持 z0–18，Terrain 支持 z0–17。不同级别隐藏过细的道路和建筑。
支持闭合面和带内环的 multipolygon；相同类型的成员面不会覆盖关系中的孔洞。
关系的线段先在交点处分段并合并重合边，再组装外环和内环，支持多个孔洞共用节点或边。
闭合性在合并前按原始线段端点检查；闭合边界沿原路折返所留下的零面积连接线，不会被误当作缺边。
这些闭合边界围成的所有有效面仍会生成；不会用直线补齐开口或直接跳过整个关系。
这不会自动补齐真正未闭合的环。与所选区域相交的异常关系、缺失引用或无法确定范围的异常仍会阻止发布。
区域 PBF 中成员完整且已知范围完全位于选区外的异常关系不会阻止本地地图导出；它们会被逐类定位，计数并列入
`map-pack.json` 的 `source_diagnostics` 和 `source-geometry-warnings.json`（最多列出 100 个例子，并标明是否截断）。
这类异常只影响选区外的低缩放背景，不能将此规则用来忽略选区内的数据损坏。
海岸线当前绘制轮廓，不生成全球海洋填色。区域 PBF 外不补全球背景数据。
建筑和道路的桥梁/隧道分层、复杂制图样式仍可后续完善。
本地生成性能取决于完整 PBF 大小和输出瓦片数，不能用小区域测试代表省级/全国生成性能。

## 验证

`dotnet test tests/TrailMateCenter.Tests/TrailMateCenter.Tests.csproj` 包含：

- 使用实际 PBF 编码的夹具生成 PNG、POI 和 manifest；
- 独立 POI 级别更换中文/英文名称后底图逐字节不变，独立 POI 名称仍变化；
- 取消某级别的独立 POI 后，中文名称进入该级别的栅格像素，manifest 也同步标明带字级别；
- 道路越过瓦片边界、带孔洞的水面、多面成员重复标签；
- 相邻孔洞共用起点/边时仍正常渲染，以及真正开环时仍拒绝发布；
- 取消、生成失败、旧图包替换、目标目录命名和输入验证；
- 应用共用导出入口的本地生成，以及旧栅格复制路径的回归。

真实区域验证工具（开发与 QA 使用，用户无需运行命令）：

```powershell
dotnet run --project tools/MapPackSmoke -- <pbf路径> <输出目录> <west> <south> <east> <north> <minZoom> <maxZoom>
```

工具调用与应用相同的本地导出服务，并在 `maps` 外生成 `preview.png` 和 `verification.json`。
预览最多拼接最高缩放级别左上角的 4×4 张瓦片。

2026-09-14 使用 Geofabrik Liechtenstein PBF 验证瓦杜兹范围
`9.51,47.12,9.54,47.15`、z14–16：生成 83 张底图、185 个 POI、46 个 POI 索引文件。
首轮本机导出约 5.8 秒（不含下载和编译）。该结果未包含设备端实际显示测试。
